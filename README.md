# مركز ؟

تطبيق مذاكرة شخصي بالعربية. يعمل بـ Next.js وTypeScript وTailwind CSS وSupabase. البيانات الحقيقية محفوظة في حسابك عبر Supabase، ولا تظهر بيانات عرض بدلًا عنها.

## تشغيل سريع

1. أنشئ مشروع Supabase مجانيًا، ثم افتح **SQL Editor** وشغّل الملف [`supabase/migrations/202610230001_markaz.sql`](supabase/migrations/202610230001_markaz.sql) كاملًا مرة واحدة على مشروع جديد. ينشئ الجداول ودوال المؤقت وسياسات العزل ومساحة `study-files` الخاصة.
2. في **Authentication → Providers → Email** فعّل البريد وكلمة المرور. لتأكيد البريد واستعادة كلمة المرور، اضبط خدمة البريد في Supabase بحسب حدود خطتك المجانية. في **Authentication → URL Configuration** ضع رابط التطبيق النهائي في **Site URL** وأضفه إلى **Redirect URLs**. للتطوير المحلي أضف `http://localhost:3000` و`http://localhost:3000/**`.
3. انسخ `.env.example` إلى `.env.local` وأدخل `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` من **Project Settings → API**. استخدم مفتاح publishable أو anon العام فقط. **لا تضع service_role في التطبيق أو Vercel.**
4. نفّذ `npm ci` ثم `npm run dev` وافتح `http://localhost:3000`.

عند النشر على Vercel: استورد المستودع كمشروع Next.js، وأضف المتغيرين العامين نفسيهما ضمن Environment Variables للإنتاج، ثم انشر. بعد معرفة رابط Vercel حدّث Site URL وRedirect URLs في Supabase، وأعد نشر Vercel إذا أُضيفت المتغيرات بعد أول بناء. ملف `.env.local` مستبعد من Git. متغيرات `NEXT_PUBLIC_*` تُضمَّن في وقت البناء؛ تغييرها يحتاج بناء جديدًا.

## ما يعمل

- حساب بالبريد وكلمة المرور، تأكيد البريد وفق إعداد Supabase، ورابط استعادة كلمة المرور. صفحة الإعداد الأولي تطلب المواد ومواعيد الاختبارات إن عُرفت، ووقت كل يوم وأيام الراحة بدون افتراض ساعات.
- مواد وجزئيات واختبارات بنطاق جزئيات محدد، وجدول حتمي يراعي الاختبار والمراجعة والفهم والوقت. مراجعة الاقتراح واعتماده صراحة، وتعديل اليوم والمدة والترتيب بأزرار لمس وتأجيل المهام. المهام اليدوية والمنجزة والمؤجلة محفوظة عند إعادة الاقتراح. المهام المتأخرة تبقى ظاهرة.
- مؤقت تركيز ٢٥ دقيقة وراحة ٥ دقائق افتراضيًا مع اختيار مدة كل جلسة، إيقاف واستكمال وإلغاء. التوقيت والجلسة محفوظان في قاعدة البيانات ويستعادان بعد التحديث. دوال قاعدة البيانات تمنع جلستين نشطتين وتكرار التسجيل. جلسة التركيز المكتملة فقط تدخل الستريك، بتاريخ `Asia/Riyadh`.
- تقييم ذاتي للفهم ودليل حل السؤال بعد الجلسة، ومراجعة للجزئيات الضعيفة. إكمال الوقت لا يعني الإتقان، والملاحظة اختيارية.
- رفع PDF حتى ٢٠ MB إلى مساحة خاصة، استخراج النص والعناوين المتاحة محليًا عبر PDF.js دون API مدفوع أو OCR، مراجعة الاقتراحات وتعديلها قبل اعتمادها، وربط الصفحات بالجزئيات. عند ملف مصور أو تعذر القراءة تظهر رسالة ومسار إدخال يدوي. روابط الملفات مؤقتة.
- PWA للشاشة الرئيسية مع صفحة واضحة عند انقطاع الاتصال، وحالة حفظ/مزامنة وفشل ظاهرة. مزامنة عند الرجوع إلى التطبيق وكل ١٥ ثانية أثناء فتحه. تصدير بيانات JSON من الإعدادات.

## التحقق

```bash
npm run typecheck
npm test
npm run test:db
npm run build
```

`test:db` يشغّل PostgreSQL محليًا عبر PGlite في الذاكرة، ويطبق ملف migration الفعلي ويفحص RLS بين مستخدمين، ومساحة الملفات الخاصة، والروابط بين الجداول، وحد الجدول اليومي، والمؤقت والتقييم. لا يحتاج مفاتيح أو خدمة خارجية. اختبار المزامنة الحية على iPhone وiPad يحتاج مشروع Supabase منشورًا وحسابين للاختبار، ولم يُجرَ قبل ربط مشروع حقيقي.

## حدود واضحة

- المزامنة وحفظ الملفات يحتاجان اتصالًا بالإنترنت ومشروع Supabase. عند غيابه تظهر حالة إعداد أو خطأ، ولا يُعرض نجاح وهمي. صفحة PWA خارج الاتصال تشرح الحالة؛ تعديل البيانات خارج الاتصال غير متاح.
- استخراج PDF نصي بقواعد عناوين قابلة للتعديل؛ لا OCR للملفات المصورة، ولا تحليل ذكي مدفوع. تقسيم الملف قبل الاعتماد يظل في الصفحة الحالية؛ بعد تحديثها يبقى الملف محفوظًا ويمكن طلب التقسيم مرة أخرى من قائمة الملفات أو إنشاء جزئيات يدويًا.
- تنبيهات الصوت والعمل المستمر في خلفية iOS غير مضمونة. مدة الجلسة تُستعاد من طوابع زمنية مخزنة، ولا تبدأ جلسة جديدة تلقائيًا.
- JSON يشمل بيانات الملف ووصفه، ولا يشمل محتوى PDF نفسه؛ يمكن فتح الملف وتنزيله من «موادي». استيراد النسخة الاحتياطية غير متاح حاليًا.
- حدود Supabase/Vercel المجانية، خاصة حجم التخزين والبريد والنطاق، قد تتغير حسب خطتهما. الوظائف الأساسية لا تتطلب اشتراكًا مدفوعًا.
