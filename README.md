# مركز ؟

مكتب عربي بسيط لفرق الشركات الناشئة الصغيرة، من أول فكرة إلى أول عميل. الواجهة بأربع وجهات: **المكتب، المشاريع، القرارات، الملفات**. تبقى أدوات الدراسة والعمل الشخصي في «مساحتي الشخصية»، ولا تُنقل بياناتها إلى الفريق.

## تشغيل ونشر

1. نفّذ ملفات [`supabase/migrations`](supabase/migrations) بالترتيب على مشروع Supabase. الملفات الأولى تنشئ البيانات الشخصية، و`202610240003` وما بعدها تضيف المكاتب والدعوات والملفات الخاصة. مشروع الإنتاج `qeflgmknxuncpiycdulj` طُبّقت عليه هذه الترحيلات.
2. في Supabase Auth، فعّل تسجيل الدخول بالبريد وكلمة المرور، واجعل Site URL هو `https://salehkjj.github.io/markaz/`. أضف هذا الرابط و`https://salehkjj.github.io/markaz/?recovery=1` إلى Redirect URLs. رابط الدعوة يُخزّن مؤقتًا في متصفح المدعو حتى يؤكد بريده ويدخل؛ لا يتطلب نطاق عودة إضافيًا.
3. للتطوير المحلي انسخ `.env.example` إلى `.env.local` وأدخل رابط Supabase ومفتاح **publishable/anon العام** فقط. نفّذ `npm ci` و`npm run dev` وافتح `http://localhost:3000/markaz/`.
4. يدفع الفرع `main` إلى GitHub Pages عبر [Pages workflow](.github/workflows/pages.yml). يستخدم السير رابط Supabase والمفتاح العام فقط. لا تضع `service_role` أو أسرارًا في GitHub أو المتصفح.

## المسار اليومي

- أنشئ مكتبًا باسم الفريق، ويمكنك إضافة مشروع وهدف الأسبوع من البداية. المالك ينشئ دعوة لبريد محدد وينسخ الرابط للمدعو. الدعوة تنتهي بعد سبعة أيام، تُستخدم مرة واحدة، ويمكن إلغاؤها. قبولها يتحقق داخل قاعدة البيانات من بريد الحساب المؤكد؛ لا يرسل التطبيق بريد دعوة تلقائيًا.
- أنشئ مشروعًا، ثم مهمة بعنوان ومسؤول واحد. الحالة والموعد والأولوية والملاحظات قابلة للتعديل في الصفحة نفسها. القائمة افتراضية واللوحة اختيارية. إكمال المهمة وتعديلها يتزامنان عبر Supabase؛ تعارض التعديل بين جهازين يظهر كخطأ ويستدعي تحديث البيانات بدل محو الكتابة.
- سجّل قرارًا مع سبب اختياري، أو موضوعًا ينتظر قرارًا. وقت اعتماد القرار وصاحبه يسجلهما الخادم؛ القرار المعتمد لا يمكن تغييره. أضف ملفًا خاصًا أو رابطًا إلى مشروع، ثم يحدد المالك مرجعًا معتمدًا. روابط تنزيل الملفات موقعة لمدة دقيقة واحدة.
- المكتب يعرض هدف الأسبوع، مهامي اليوم، ما يحتاج قرارًا أو مساعدة، وأقرب تسليم. متابعة الأسبوع تجمع عدد المهام المرتبطة بالهدف والتحديثات النصية «تم، التالي، العائق» من الفريق دون تحليل مدفوع أو ترتيب أفراد.
- «حركة الطماطة» اختيارية من المهمة. الجلسات والنقاط ومسار الاستمرار لعشرة أيام شخصية حتى داخل المكتب. تحفظ الجلسة بالطوابع الزمنية، ويمكن استكمالها بعد تحديث الصفحة. الجلسة المكتملة لا تكمل المهمة آليًا؛ يسجل المستخدم نتيجتها بخطوة قصيرة. أدوات PDF والتقييم الدراسي متاحة من المساحة الشخصية.

## صلاحيات البيانات

كل مكتب له عضويات `owner/member`. تمنع RLS غير الأعضاء من قراءة وتعديل جداول المكتب وملفاته. إنشاء العضوية والدعوة وإلغاؤها يمر بدوال خادم تتحقق من `auth.uid()` وبريد الحساب المؤكد. لا تسمح جداول العضوية بكتابة مباشرة من المتصفح. مساحة `office-files` خاصة، ومساحة `study-files` الشخصية مستقلة. لا تعرض جلسات التركيز الشخصية أو نقاطها للزملاء. رفع الملفات محدود إلى ٢٠ ميغابايت للملف في إعداد التخزين.

## الاختبارات والحدود

```bash
npm run typecheck
npm test
npm run test:db
npm run build
```

`test:db` يستخدم PGlite محليًا ويطبق الترحيلات الفعلية؛ يفحص مستخدمين منفصلين، الأدوار، الدعوات الملغاة وبريد المدعو، عزل المكاتب والتخزين، حفظ بيانات الدراسة السابقة، المهام والقرارات والمؤقت. فحص الواجهة المحلية يشمل عرض iPhone وiPad وRTL ومسار `/markaz/`. اختبار مزامنة حية بين جهازين بحسابين فعليين يحتاج حسابي اختبار مؤكدين؛ اختبارات PGlite لا تثبت أداء شبكة Supabase على جهازين.

تحميل السجلات الحديثة محدد إلى ١٠٠ صف مع زر «اعرض المزيد» للمهام والقرارات والملفات. في مكتب ضخم يتجاوز ذلك قد لا تشمل بطاقة المكتب كل السجلات القديمة حتى يحمّلها المستخدم؛ المنتج مصمم لفرق ٢–٨ أشخاص. لا يوجد إرسال تلقائي للدعوات، ولا إشعارات خلفية مضمونة على iOS، ولا تحرير دون اتصال. وظائف المكتب الأساسية لا تتطلب API مدفوعًا؛ تخضع لسقوف Supabase وGitHub Pages المجانية.
